# 下一篇怎样加入

## 最方便的对话用法

下次提供论文和阅读分析时，可以直接指定：

> 按Meta-method v0.4.0分析这篇论文，并生成论文库入库单。先检查arXiv、DOI和旧别名。分开作者贡献、我们的审查和后续提案。保留阅读范围、论文版本、首项判别证据与继续/停止条件。已有条目追加分析；没有评过的潜力留空。

在新的会话中，需要提供当时最新的论文库包或可访问的库目录，才能检查重复和保留历史；不能假定本次沙盒永久充当服务器。

## 页面路径

打开index.html → 新增/复读 → 填写分析 → 导出reading-intake.json → 放入inbox → 执行：

```bash
python3 tools/library.py add inbox/reading-intake.json
```

从论文详情点“为这篇追加分析”会自动填入固定编号和链接。页面只能导出文件；导出不等于入库，入库不等于推送GitHub。

## 填写范围

首次入库只需标题、分析正文、来源说明。建议同时提供arXiv/DOI、主题、框架和论文版本。没有后续方向、代码或分数都可留空。不要为了完整性把猜测补成事实。

可以在`sections`里分别写原有局限、作者操作、增量、证据范围。`ideas`每项独立写title、question、first_evidence和decision_branches；原文作者建议与我们的新提案需在文字中说明，不自动算作者已完成的操作。

## 潜力评价规则

历史10分制继续兼容，但不自动新增分数。评价时分别考虑问题价值、与近邻工作的区别、最小证据判别力、资源可行性和可迁移范围；没有独立核验时明确说明。不要强行给五项任意权重，或把总分变成接收概率。

同一论文可能有多条潜力不同的方向。先给具体方向评分通常比只给整篇评分更有用；论文级旧分只是主线历史优先级。记录条件变化、负结果、近邻新工作和预算变化造成的升降分。

## 更正与复读

正文内容更新用add追加，保留旧记录。完全相同正文重复导入视为无变化。只有元信息需要纠正时也应写一份简短更正说明，明确paper_id并保留原观察。别把新版本标题变化当新论文。

## 迁移与备份

整个目录可直接复制，JSON/Markdown是唯一必需的长期数据。网页是派生视图，可随时重建；不依赖专有笔记服务或数据库。每批加入后保存一个不覆盖既有文件的ZIP备份。
