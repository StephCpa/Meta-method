# M13：组合增量记录，而非自动创新证书

L1–L7名称来自提供的审查L104–L123，完整目录尚未取得。本表是待试用的增量检验，不是封闭必要条件集合。一个方案不需要证明A与B具有统计学超加性，才能具有新能力或成本贡献。

**已有部件：**A是什么、B是什么、最接近的直接组合是什么？

**原有障碍：**具体哪一种目标、信息条件、证明步骤或资源边界不能被解决？

**改变的关系：**组合后究竟改变哪个接口、条件、计算对象或行为关系？

**新增结果：**与已有工作相比增加什么；不要只写“更全面”“更鲁棒”。

**证据与范围：**原文已提供、当前提出、尚待核验分别记录；与贡献类型匹配。

| 外部lift提示 | 必须落地的检查 |
|---|---|
| L1 精确对应／推导 | 新关系究竟是什么，相对既有推导增加什么？ |
| L2 意外结果 | 相对于何种明确预期，是否有可靠且重要的差异？ |
| L3 新能力 | 新的可完成任务及以前做不到的条件是什么？ |
| L4 远距离结合＋具名障碍 | 哪个性质通过映射被保留，哪个障碍确实被越过？ |
| L5 机制诊断 | 哪些替代解释被区分，新增认识在哪里？ |
| L6 真实环境验证 | 现实条件揭示了什么新边界，不只是更换测试地点？ |
| L7 现实威胁模型 | 攻击能力与可信边界改变了什么可证明或可实现结果？ |

可以填写other：放宽限定假设、简化、负面结果、公共工具等。只有标签没有新增结果及证据，应记“增量未确立”，而非立即“无价值”。

反模式：只有新术语；无法指出比较对象；以未计账额外资源归因于新算法；把新测试集当作新机制；先声称组合无效却忽略其已建立的新能力。已有组件＋扩大资源若使新规模可行，应按系统贡献评价，不能一票否决。
