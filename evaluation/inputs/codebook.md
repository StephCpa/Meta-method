# M1–M14 操作代码本

编号兼容历史对话。它们是可重叠的操作，不是互斥的论文类型或完成清单。生成阶段可先写机会和候选变换；进入审计时再写主张及证据配置。

## 操作角色与来源角色分别记录

M编号保持兼容，但不再作为同一平面的创新类别。`generative_move`表示产生研究可能性的操作，`evidence_check`表示证据检查，`implementation_technique`表示实现技术，`combination_overlay`表示组合结构；同一技术可在不同工作中承担不同角色。

M14主要是证据检查，不因频繁用于审稿而成为最常见创新；M4的负控制与弱模型组件分开；M10的机制发现可能本身是贡献，不机械删除。

## 三种来源必须分开

- `author`：有原文定位支持的作者已采用操作。只有摘要或二手描述时，注明定位与核验范围，不推断真实发现顺序。
- `review`：分析者使用的审查动作，不能计入作者方法频率。
- `proposal`：待执行的后续方案，不可写成已观察结果。

每条编码记录代码、来源角色、证据锚点、理由和排除相邻解释。未知可空缺，不以填码数量评分。

| 代码与历史名称 | 纳入标准 | 排除／边界 |
|---|---|---|
| **M1 诊断后干预** | 诊断区分了相关情形，并实质改变后续设计或行动 | 引言中列不足不够；不干预也是可能结果 |
| **M2 表示／基本操作重写** | 改变基本对象、状态空间、预测单位、计算原语或信息协议，并说明增量 | 换名、换骨干、常规换数据集不自动算 |
| **M3 预算／瓶颈重分配** | 明确真实瓶颈、主约束与资源替代，报告完整成本 | 只宣称更快或比较不可比工作负载不够 |
| **M4 弱模型／负控制引导** | 使用有目的的弱化组件提供方法信号，或构造机制应为零的对照 | 弱模型不是天然负控制；一般去组件不自动识别机制 |
| **M5 反馈闭环** | 中间反馈实际改变后续生成、搜索、训练或数据选择 | 重复运行同一流程、不使用反馈不够 |
| **M6 数据／反馈通道扩展** | 将原未利用的偏好、过程反馈、长尾或领域信息变成可使用的接口 | 仅增大数据量不自动算；信息真实、可学、有用分开 |
| **M7 评价协议重构** | 改变估计目标、评价单位、抽样／选择分离或决策协议 | 多报一个常规指标、增加一般消融不够 |
| **M8 跨层共同设计** | 模型、系统、硬件、协议或验证器围绕明确共享约束联合设计 | 多模块拼接、分别调参不自动算 |
| **M9 隐含假设形式化** | 显化量词、条件、不变量、目标关系、逻辑性质或可执行契约 | 写公式不等于保证；假设也不自动是缺陷 |
| **M10 设计空间搜索与机制归因** | 预先界定相关变体及比较条件，或以反事实排除替代解释 | 调参获胜、普通消融不能单独证明因果机制 |
| **M11 结构迁移／桥接** | 明确中间映射及保留性质、误差或边界 | 概念相似、跨领域叙事不够；不要求桥接必然改善模型 |
| **M12 中间抽象／统一接口** | 建立语义明确、可复用且可检查的组件接口 | 模块化代码或一张架构图不自动算 |
| **M13 A+B 组合（控制码）** | 记录组合事实，判断额外产生了什么 | 需写出原有限制→改变关系→新增结果→证据；见组合增量记录，标签不是创新证书 |
| **M14 支持集与估计量双重闸门** | 检查对象定义、可观测性、真实目标层级的信息量和估计工具有效性 | 未检出≠不存在；局部弱≠总体不可估；不要求干预前已有待学习能力 |

## M4 的内部注明，不新增编号

`method_signal` 表示退化／弱模型是实际方法组件；`negative_control` 表示按机制假说本应无目标效应的证据对照。使用时写明保留了哪些混淆、移除了什么作用。两种角色可共存，但不得相互替代。

## M14复验触发（M14′，不是新编号）

当诊断指标、内部特征、参考判断或评价规则进入训练目标、样本选择、路由或停机控制时，重新检查其与目标属性的关系。区分目标属性、样本分布、表示／测量工具、标签定义四种变化；不能只用被优化指标自身上升验证有效性。

记录measurement_recheck：not_triggered／triggered_pending／revalidated／inconclusive。revalidated表示完成了所记录的检查，不自动表示结果支持有效；结果在evidence_refs中另记。没有相应反馈影响时不触发，不强求新训练实验。公开开发案例限制只针对开发使用历史，不针对“合成”这个生成方式。
