# M1–M14 glossary

Identifiers retain the Chinese [codebook](codebook.md) meaning. They are optional operations, not a taxonomy of scientific value. `author` marks an annotation about the paper’s move; `review` and `proposal` mark audits and proposed extensions.

| Code | English label | Permitted roles (context dependent) |
|---|---|---|
| M1 | Diagnosis-informed design | generative_move, evidence_check |
| M2 | Representation or primitive redesign | generative_move |
| M3 | Budget and bottleneck reallocation | generative_move, implementation_technique |
| M4 | Weak-model guidance / negative controls | generative_move, evidence_check, implementation_technique |
| M5 | Feedback-loop construction | generative_move, implementation_technique |
| M6 | Data or feedback-channel expansion | generative_move, implementation_technique |
| M7 | Evaluation-protocol redesign | generative_move, evidence_check |
| M8 | Cross-layer co-design | generative_move, implementation_technique |
| M9 | Formalizing assumptions and contracts | generative_move, evidence_check |
| M10 | Design-space exploration / mechanism attribution | generative_move, evidence_check |
| M11 | Structural transfer and bridging | generative_move |
| M12 | Intermediate abstractions and interfaces | generative_move, implementation_technique |
| M13 | Combination overlay: A+B | combination_overlay |
| M14 | Support and estimator gates | evidence_check |

A source-anchored move is not a verified cross-domain recipe. A lift is a substantive added result, not automatically statistical superadditivity. A completed contribution need not produce a new trained model.
