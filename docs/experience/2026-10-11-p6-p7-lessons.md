# 从 P6／P7 实际推进中修订 Meta-method：经验记录与执行建议

日期：2026-10-11。文档版本：1.0。基准：Meta-method v0.4.0，远程 main 快照 `921c1f1d8f2258e5ab7899bdfe96527cb841d2f8`。

**性质：回溯性 development 记录＋候选执行规则，不是新框架版本，不是对框架有效性的独立验证。**本次只整理经验；没有重新运行 P6／P7 模型、PDE 实验或用户服务器代码。已读附件、对话报告、审查判断与建议分别记录于[证据台账](2026-10-11-evidence-ledger.md)。原始报告中的强结论不因被收录而获得确认。

## 0. 核心结论

这轮经验不是要求再增加一套庞大的审计清单，而是将检查前移、缩短无信息迭代，并保护真正值得构造的方向：

> **先识别值得解决的障碍与最强简单路线，再校准实际接口；实验产生意外后，先区分实现、目标、指标与机制，再决定重构、确认或停止。失败不自动变成新机制，停止也不需要证明所有变体永远无效。**

P6 提醒我们：初始算法未获支持，可以形成新的监督关系假说，但不能从配对冻结、低记忆读数或一次增益直接推出机制。P7 提醒我们：一个数学上合理的采样改进，可能从开始就输给预计算、精确小系统与变量消元；后续机制叙事同样需要自己的证据，不能成为保住项目的默认退路。[E1–E6]

本次不新增 M15 等编号，不覆盖 R01–R12，不修改论文库、原始实验、已签协议、预算或许可证。下文 E01–E12 只是本文的建议编号；每项只在对应问题出现时启用。

## 2. 四个前置关口：不是新增四项必做实验

| 时点 | 一页内要回答的问题 | 可接受的最小产物 |
|---|---|---|
| 立项前 | 真正目标是什么？是否必须学习、随机化或构造昂贵对象？同样信息与资源下，最强简单方法是什么？ | 问题结构与基线卡；可能只需推导或现有程序 |
| 长运行前 | 当前代码实际优化什么？目标、标签、输入、随机流、评价与成本是否对应？ | 一批数据上的输出／损失／梯度或决策对拍 |
| 意外结果后 | 是对象改变、指标混用、实现错误、优化未完成，还是机制候选？下一动作区分什么？ | 变更影响表＋一个优先干预，不自动扩大网格 |
| 追加投入前 | 旧路线是否已失败？新问题有何独立价值？还有哪些便宜解释？资源是否重新批准？ | 停止／重写／确认记录，含上限和退出条件 |

理论工作不必跑 GPU；资源／数据工作不必产生新 loss；有完整形式化目标的研究不必先找到现实模型失败。关口检查的深度由本次主张决定。[框架 R01–R12]

## 3. 十二项可操作的修订建议

### E01｜把“是否需要这项复杂技术”放在校准之前

**触发经验。**P7 的冻结、无噪声、低维参数问题，在少量位置提供满秩精确方程时，可以由简单计算恢复参数。先建复杂随机梯度，并不会让这个问题天然需要随机化。[E3、E5]

**建议。**生成候选后先画出必要计算链：哪些量必须反复计算，哪些可缓存；哪些参数可消去，哪些可闭式求解；是否必须估计完整对象；是否可直接执行规则或查询数据库。为最强简单路线提供与候选相同的原始信息与调优机会。

**验收。**写出复杂技术的具体生存条件及预计改变的成本／能力边界。精确基线能直接解决时，可以停止，也可以带着明确的新问题重新立项；不能为保住算法而悄悄升维、加噪或移除基线可用的信息。

**不应过度执行。**建设可复用工具本身可以是贡献；不能要求一开始证明复杂方案最优，也不能把所有可解问题都视为无价值。映射：R02、R04、R10、R12；M2、M3、M12。

### E02｜按数学结构和信息接口查新，而不是只搜方法名

**触发经验。**P7 初期围绕 STDE／PINN 搜索，成熟的测量误差、校正矩、变量投影和弱形式没有及时成为实质基线。近期多轮／多 Agent 选题也表明，标题不同的邻近工作可能已实现同一修复动作。[E6、E8]

**建议。**把候选翻译为“对象＋观测方式＋算子＋目标＋预算”后再查文献。例：冻结场线性系数与噪声特征，先问是否是含噪协变量回归；选择子集求导，先问是否是分层／多阶段抽样；共享状态撤销，先问是否是依赖维护与事务问题。

**验收。**每条主线至少列出最近的同领域方法、最接近的经典结构，以及能否省略该计算步骤的替代路线；明确已经排除的旧创新表述。材料只读到摘要时保留深度限制。

**不应过度执行。**结构相似不等于问题完全解决；需检查假设和执行成本。本文只记录此前审查识别的缺口，不声称本次重新核验全部文献。映射：R01、R02、R11；M11、M13。

### E03｜已知公式的数值通过，优先记为验证而非发现

**触发经验。**P7 将方差分配律与期望互换的 MC 重现由“机制发现”收紧为实现验证。P6 的排列距离接近随机期望，也不能单独识别成本无差别的机制。[E1、E4]

**建议。**分别记录：公式的数学状态；代码是否实现公式；构造是否具有代表性；真实系统是否表现出该效应；它是否改变决策。已知零／非零控制通过后，继续增加控制必须能解释尚未解决的歧义。

**验收。**每个新结果有 `evidence_role` 与适用范围：例如已知恒等式的实现核对、受控存在性构造、经验比较、机制干预。MC 与解析结果偏离时，用可核验的方差／标准误或精确小例定位；不能仅凭重复数称为噪声，也不能仅凭一次最大偏差称为新现象。

**不应过度执行。**新的数学定理可以独立构成贡献；不要求它再经过模型训练。映射：R03、R05、R09、R11。

### E04｜给指标绑定完整身份，先执行表格一致性检查

**触发经验。**P7 的 ever-hit 被当作 final-hit；场参数误差被当作场函数误差。P6 的 validity、unseen-valid、unique novel 与 creativity，以及 256／2048 生成预算下的读数，曾存在混用风险。[E1–E4]

**建议。**每个主要数值绑定：对象、分子／分母、单位、条件子集、样本数、聚合单位、时间点、checkpoint 选择、评价器版本和成本边界。仅增加名称而不固定含义没有用。

**最低检查。**同一阈值与同一终点下，100% 达标不能同时伴随超阈均值；ever、final、持续达标和达到时间分列。参数坐标误差和函数误差需要显式映射。有限采样覆盖 `unique_novel/N` 是 N 的函数，不跨 N 直接比较方法。

**验收。**论文主表由同一份逐运行记录生成；支持回查到 seed、checkpoint、评价样本。结构测试只发现数值矛盾，不替代科学判断。映射：R01、R05、R06、R09；M7。

### E05｜区分数据配对、条件输入、损失目标和实际更新

**触发经验。**P6 中 TL 与 NTP 使用不同答案配对，并不自动意味着它们在同一个条件输入上接收冲突标签；目标变化还可能改变后续 Hungarian 轨迹。P7 的 B/C 混合更新一般也不能自动视为某个共同标量目标的梯度。[E2、E6]

**建议。**为每个分支记录实际输入、labels、mask、权重、随机流、梯度路由和优化器。明确估计的是同目标的不同算法，还是不同训练程序的整体效果。进行配对或损失修正时，teacher-forcing 输入必须与相应标签一致。

**验收。**先比较一批样本上的目标标签与损失；需要更新等价时再比较梯度／参数位移。不同配对、不同标签、负梯度内积和优化目标不可兼容是不同主张，不互换名称。

**不应过度执行。**有意改变目标可以是贡献；目标不一致不是自动错误。映射：R03、R07、R08；M2、M9、M10。

### E06｜同目标精确加速、代理路线取舍、系统收益三张账分开

**触发经验。**P6 先有不同代价路线的 3.89× 耗时比，后续才报告同代价矩阵复用的一致性与约 2.6× 计时。P7 的解析坐标求值账本不等于 A6000 的壁钟竞争；弱形式也不能按零 jet 当作零成本。[E2、E5]

**建议。**精确计算加速先核对相同输出，涉及训练则核对必要的梯度；代理方法比较精度—成本，不称为相同运算被加速；系统比较包含数据、pilot、构建、编译、缓存、验证、失败和重试。

**验收。**一次 API／forward 调用不是固定工作量。记录实际序列、token、算子、场前向、反向及共享计算；冷启动与稳态分列。所有合法的预计算、缓存、闭式求解、弱形式和提前停止机会，对基线同样开放。

**不应过度执行。**理论成本模型可以独立成立，但必须写出模型；不可把工具尚未优化的实现性能当作整个方法家族的限制。映射：R07、R10；M3、M8。

### E07｜机制名称不能代替驻点、干预或因果证据

**触发经验。**P6 的冻结与大配对差距支持稳定选择，不证明冻结导致坍缩；记住训练配对也不必然破坏生成。P7 的终点损失同量级与目标分解，不足以证明同一伪盆、衰减入盆或近正交性。[E1–E6]

**建议。**时间先后与预测关联先作为现象。机制主张逐个问：什么不含该机制的程序也会产生这个曲线？是否已收敛？是否存在共同目标？当前分解是否只是代数分解？

**优先干预。**复用现有 checkpoint／矩阵：锁定与在线相同配对、回放已学映射、固定场重新求系数、消去线性 nuisance 参数后的低维目标检查。等价分支是实现测试，不算两个独立学习方法。

**验收。**驻点、吸引区域、局部极小、有限步停滞分别表述；终点向量分解可定位误差，却不是唯一机制贡献率。不要仅因范数一大一小就命名正交性。映射：R03、R07、R09；M9、M10。

### E08｜实现事件冻结旧结论，并可转成显式、独立的变体

**触发经验。**P6 的数据展开、标签配对、memo 前缀和 evaluator 事件改变了对同一现象的判断；旧偏差版的有利结果后来形成新的目标关系假说。P7 的 einsum／归一化错误与校正矩数值问题也经历撤回。[E1–E4]

**建议。**发现事件后记录受影响运行、失效主张、仍有效证据和恢复条件。旧输出保留，标 invalid／superseded；修正后从预定起点对照，不把无意实现直接改名为已验证方法。

**生成机会。**一个实现偏差可以启发新的构造，但必须显式定义它，重建该目标，与同环境简单基线独立比较。异常的价值来自后续可检验的变换，不来自“bug 反而更好”的故事。

**验收。**自检覆盖输出、损失和实际使用路径；同一段代码用来生成答案和判真值时，还需独立实现或已知控制。主仓旧失败不静默修复；对照复跑的结论限于实际复现的失败。映射：R06、R08、R09、R12。

### E09｜确认集由使用历史定义，不由文件哈希定义

**触发经验。**P6 报告已冻结 2048 个 hash 与多种子决策规则，但后续读数是否参与候选和超参数选择仍需依原协议核对。P7 的正则下限事后选择、最佳真值误差 checkpoint 也是开发性选择。[E2、E4]

**建议。**记录数据的生成、读取、调参和决定用途。文件固定不等于决策未受结果影响；新生成样本也不自动代表新问题家族。比较使用同一指标与生成预算；训练 seed、任务、用户和消息不是可互换的独立单位。

**验收。**保留原已签判据，不因新结果临时改成功定义；若已发生影响选择的读取，新增确认需另记。项目继续阈值与统计推断分开，例如“三种子全正”不能单独写成充分显著性。

**不应过度执行。**协议允许的中期检查并非一律污染；探索可以改题，但改题后的证据地位要保留。映射：R06、R09、R12。

### E10｜授权、真实信息和实际完成是三个对象

**触发经验。**Case002 的成对世界需要语义自洽；无关改写稳定不自动排除盲从。LLMLostMA 后续将同一份有用纠正放进正常与混合注入分支，防止整体拒绝被算作成功。[E8]

**建议。**构造任务前写明谁有权改变什么、什么属于事实证据、什么属于行动指令。自动答案只保证规则内的计算，不保证自然语言任务定义合理。来源更可信、时间更晚或多 Agent 同意，不自动给予任意操作权限。

**验收。**分别报告有用信息采纳、合法工作完成、越权尝试和实际副作用。对观察上不可区分却要求相反动作的世界，登记信息缺口，不当作模型失败。工具动作必须实际执行并取得回执。

**不应过度执行。**本项仅适用于相应语义／权限／执行主张，不加到纯数值或理论研究。映射：R01、R04、R05、R08。

### E11｜停止的是当前投入；重开必须有新机会而非未测试角落

**触发经验。**P7 从采样器转向场路径、噪声交叉和高维可能性时，出现了“只要还有未测体制，就继续保留主线”的风险。P6 也存在从 60 GPU 小时上限自然扩成更大确认计划的预算缺口。[E2、E3、E5、E6]

**建议。**一张停止卡只需说明当前候选、设置、最强已执行基线、未决范围和资源决定。无需证明所有同类方法永远无效。噪声增大、参数升维、换模型和加长训练属于任务／证据变更，不能默认获准。

**重开条件。**有独立的重要问题；简单解释尚有具体缺口；下一证据可改变明确决策；新投入有上限。允许一次界定清楚的收尾检查，不把“收尾”循环变成无期限的新阶段。

**验收。**已用、在途、已批准追加、待批准追加分列；条件触发不自动增加总额。停止方法可保留记录、代码、负结果；不能预设“采样器输了至少还能写机制论文”。映射：R10、R11、R12。

### E12｜AI 推荐与审查也应接受版本、来源和价值检查

**触发经验。**两个模型都推荐同篇获奖论文，不构成独立立项证据。近期查新改变了多轮／Agent 方案；部分外部引文纠错后来又被来源反证。P7 的规划者也需要下调最初对采样切口的优先级。[E6–E8]

**建议。**推荐要记录可核验的最近邻、资源与专业核验要求、最有可能失败的理由。审查意见也是带出处的主张，不能因其语气专业而全盘采纳。缺少证据与批评错误都允许明确记录。

**验收。**每轮审查最多优先一个真正阻塞决策的问题；新增检查需说明会改变哪个行动。已经解决的检查不要重复要求。记录生成候选的质量、保留与误删、实际独立增量，而不是只统计审查条数和通过的测试。

**边界。**本次案例全部参与过规则形成，不能用它们证明这些新建议已经提高科研成功率。映射：框架 §6、R06、R09、R12、MM-G01。

## 4. 不让经验沉淀再次退化为“只有审计”：四张候选生成提示

这些是下一版生成卡的候选附注，不是已经验证有效的新 M 码，也不自动生成四个项目。

| 触发情境 | 可尝试的对象变换 | 第一个产物 | 淘汰标准 |
|---|---|---|---|
| 需要的输出低维、内部求解很大 | 先消去可解的 nuisance 变量，再研究剩余对象；例如 P7 的场／参数可分离结构 | 与现有变量投影等强方法比较的简化计算或新边界 | 只是重写已有方法、没有新能力或成本差异 |
| 两分支使用同一数据但结果分化 | 保持边际数据、监督量和权重，显式改变分支间的耦合关系 | P6 中定义清楚的四格／端点对照 | 优势来自额外监督、标签错误或过弱基线 |
| 完整昂贵对象只用来作选择 | 检查哪些变换保持最终选择，直接计算有用的差异 | 相同决策与更低成本的对拍；配对代价可先检查不变性 | 代价数值差大但决策相同，却误称机制改变 |
| 防御会丢掉完成任务所需的信息 | 将证据内容与操作许可分离，比较选择性保留而不是全部拒绝 | 同一有用信息、不同越权成分的可执行配对 | 简单作用域检查已足够；收益仅来自更多拒绝 |

上述变换的价值必须扣除经典与最新近邻，避免将“删去不必要步骤”“跨分支分工”“保留有效信息”这些一般原则重新包装成新算法。

## 6. 可直接复制的轻量记录

### 新候选／重开卡

```text
目标与价值：要新增的认识、能力或资源边界。
现有机会：为什么现在值得，而不是因为旧方案输了。
最强简单路线：同样信息、合法缓存／闭式／执行条件下能做到什么。
最近邻与剩余增量：已做、未核对、仍待验证分别写。
本次改变：具体对象或关系；哪些条件保持。
首个产物：一个能改变决定的证明、对拍、观测或实现。
证据范围：验证／经验／机制／系统分别界定。
决策分支：继续、保留简单方案、信息不足、结束。
资源：已用、在途、本次上限、再次批准条件。
```

### 运行结果卡

```text
run_id / code_commit / data_version / environment / random_streams
training_objective / branch_inputs / target_mapping / actual_update
metric_name / formula / units / denominator / subset / sample_budget
checkpoint_rule / final_or_ever / aggregation_unit / independent_repeats
measurement_cost / total_cost / invalid_or_failed_runs
what_was_checked / what_remains_unchecked / claim_status / work_status
```

草稿可以留空；理论、用户研究、数值分析与安全任务选择适用项，不要求每项都填写训练字段。

## 7. 如何检验这些建议本身

本文是 P6／P7 发展过程中的回溯提炼，不能以发现了多少错误、避免了多少声称的 GPU 小时来宣布成功。未执行的实验是否本来会执行，通常没有直接反事实。

下一次冻结后的新机会中，可比较旧版 v0.4 工作流与采用这些附注的流程，保持材料和总预算相近，记录：是否更早识别已解决的结构、首项实验是否更有判别力、是否误杀有价值的方向、原始候选如何被改写，以及确认后实际产出了什么。不以停止数最大、检查数最多或填码率最高为目标。

P6／P7 及参与本次修订的相近材料均作为开发集；新生成 hash 或同一个问题家族的变体不自动成为这项框架评价的独立留出。

## 8. 当前结语

**P6：**依据用户 2026-10-11 更新，目标分支关系仍在确认中；本次不提前判成功、不修改已签判据或预算。

**P7：**来源报告已停止冻结场新采样器。后续审查建议不再以未测角落维持主线，只允许界定清楚的低成本机制收尾；这是一项投入建议，不代替项目负责人执行状态。伪盆、衰减入盆、115% 噪声交叉点与“物理合理范围”仍需保留证据边界。

最值得沉淀的不是“所有研究必须更严格”，而是：

> **把严格性用在最能改变下一步的位置；让生成、审计和停止都服务于新的知识与能力，而不是服务于最初的想法必须获胜。**
