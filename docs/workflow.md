# 使用流程与状态管理

## 从机会起步

尚无精确主张时，先写[机会—贡献卡](../templates/opportunity-to-contribution.md)，可使用[结构化模板](../templates/opportunity.json)。依次明确情境、限制、候选变换和可能增量。没有成熟提案时保持draft，不强填主张卡。使用过M码不是完成标准。

候选具体化后再进入下面的主张审计。保存原候选；审计后的改写另记派生版本。组合方案附M13增量字段，无组合时不要求填写。

## 轻量起步

先填写贡献—证据卡的前五项，不要求立即具备全部数据。区分研究机会、核心主张与当前未知；选择一个或多个证据配置，再决定是否需要M代码。代码不是提交卡片的必要条件。

## 下一项证据行动

选择最可能改变重要判断的证明步骤、原型、观测或实验。写出至少一种“仍无法区分”的结果，不强制所有结果落入两个互斥机制。对探索性构造，可以先声明可行性里程碑，再随观察修订问题。

## 主张与行动是两种状态

主张状态可为 draft／under_review／supported／refuted／inconclusive／withdrawn。工作状态可为 exploring／planned／active／complete／paused／stopped／rewritten。

- `complete`：当前研究工作已在声明范围内完成，主张可能被支持，也可能被反驳或收窄；记录完成依据，不把完成自动等同于正面结果，无义务补成新算法。
- `paused`：当前信息或资源不足，说明可解除条件。
- `stopped`：在当前目标与预算下不再继续；不冒充终生不可能。
- `rewritten`：目标或证据类型改变，保留旧卡与原因，不能保留旧强结论同时降低要求。

机器检查只审计记录结构，不决定科学主张真实或工作必须停止。

## 版本与独立确认

每次修改记录版本、日期、改变的主张、触发证据、哪些旧证据仍适用。开发材料不得在改名后成为确认集。模型训练知识造成的潜在熟悉度也需承认：分析者“未读过”不等于模型未见过。

## 下一阶段里程碑

1. 独立复核首轮作者操作锚点和粒度，保留分歧。
2. 在新的机会情境上比较具体生成卡与强通用指南，不以已知赢家作为唯一答案。
3. 保留MM-P01审计评价；MM-G01另评生成、固定池选择和实际下一步。
4. 实际模型、材料、预算和评审绑定后重新冻结；内容哈希不是正式预注册。
5. 对结果未知的研究决策检查知识／能力增量与误停，不强制每项工作训练新模型。

## 记录闭环

结构化记录加入claim_status、evidence_refs/evidence_outcome、decision_branches、revision_effect与measurement_recheck。checked仅表示做了核验；即使refuted也可能完成研究；inconclusive+paused不是否定。新字段对草稿可选，结束状态需可追溯，工具不会判定证明真实。例见 [结束状态](../examples/end-states.md)。

留出候选的生成方式与污染历史分开；先按provenance声明审查，未知返回needs_review，不默认通过或仅因合成而拒绝。默认工作验证可增长，旧发布完整性用独立快照检查。当前迁移范围见CHANGELOG与STATUS，不依赖外部补充包使用本版。
